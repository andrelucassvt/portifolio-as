# Flow: Internacionalização (pt-BR · en · es)

> **Resumo:** Tradução client-side de todas as páginas (index, apps, ir/*) para pt-BR, inglês e espanhol: atributos `data-i18n*` no HTML + dicionários em `locales.js` + dropdown de idioma com bandeiras no header, com escolha persistida em `localStorage`.

## Visão Geral

O HTML continua escrito em pt-BR (conteúdo visível sem JS e para buscadores). Ao fim do `<body>`, `locales.js` expõe `window.LOCALES` (um dicionário chave → texto por idioma) e `i18n.js` escolhe o idioma, percorre os elementos marcados com `data-i18n*` e troca texto, HTML ou atributos. O mesmo ocorre ao escolher uma opção do dropdown `.lang-switch` do header (botão com a bandeira/código atual que abre um menu com Português, English e Español; as bandeiras são `<symbol>` SVG inline no sprite `.svg-sprite` no início do `<body>` de cada página).

O idioma inicial vem, nesta ordem, de: escolha salva em `localStorage` (`as-lang`) → idioma do navegador (`pt*` → pt-BR, `es*` → es, `en*` → en) → inglês para qualquer outro idioma. Sem preferência detectável, mantém pt-BR. Como a chave é compartilhada por origem, a escolha vale em todas as páginas do site.

`main.js` consome a API `window.i18n.t()` para os textos dinâmicos (rótulo "Copiado", `aria-label` do menu) e escuta o evento `i18n:change` para re-sincronizar o que não é marcado no HTML.

## Passo a Passo

1. **[Marcação]** — `index.html`, `apps.html`, `ir/<slug>/index.html`
   Elementos traduzíveis recebem `data-i18n` (texto), `data-i18n-html` (inclui `<em>`/`<code>`) ou `data-i18n-attr="attr:chave;…"` (aria-label, alt, content de metas). `data-i18n-name` preenche `{name}`.
2. **[Dados]** — `assets/js/locales.js` → `window.LOCALES`
   Três objetos (`pt-BR`, `en`, `es`) com as mesmas chaves.
3. **[Boot]** — `assets/js/i18n.js` (IIFE, executa ao carregar, antes de `main.js`)
   Registra o dropdown (`initSwitcher`: abrir/fechar no trigger, fechar com clique fora ou Escape, setas ↑/↓ entre opções) e chama `setLang(detectLang(), { persist: false })`.
4. **[Detecção]** — `i18n.js` → `detectLang()`
   `localStorage["as-lang"]` válido → `navigator.languages` → fallback `en`.
5. **[Aplicação]** — `i18n.js` → `setLang()` → `applyTranslations()`
   Define `document.documentElement.lang`, traduz `[data-i18n]` (`setText`: em elementos com filhos troca só o primeiro nó de texto solto, preservando ícones e espaços), `[data-i18n-html]` e `[data-i18n-attr]`; atualiza o seletor em `syncSwitcher` (`aria-current` na opção ativa, bandeira/código/`aria-label` do trigger), grava a escolha (exceto no boot) e dispara `i18n:change`.
6. **[Troca manual]** — clique em `.lang-switch__option[data-lang]`
   Chama `setLang(lang)` com persistência, fecha o menu e devolve o foco ao trigger.
7. **[Textos dinâmicos]** — `assets/js/main.js` → `t()`, `initMobileNav()`, `initCommandCopy()`, `initShortLinkCopy()`
   Usam `window.i18n.t()` (com fallback pt-BR se `i18n.js` não carregou); `initMobileNav` reaplica o `aria-label` do toggle em `i18n:change`.

### Caminhos alternativos

- **Chave ausente no idioma ativo:** `translate()` cai para pt-BR; se também faltar, devolve a própria chave.
- **`localStorage` indisponível:** `readStoredLang`/`storeLang` engolem a exceção; a escolha vale só até recarregar.
- **JS desligado:** a página fica em pt-BR e o seletor é ocultado por `html:not(.js) .lang-switch` (`_lang-switch.css`).
- **Páginas `ir/<slug>/`:** não têm seletor; seguem o idioma salvo/detectado.

## Regras de Negócio Relevantes

- **Idiomas suportados:** pt-BR, en, es — `SUPPORTED` em `assets/js/i18n.js`. Navegadores em outros idiomas recebem inglês.
- **pt-BR duplicado de propósito:** o texto existe no HTML (SEO/sem JS) e em `locales.js`; editar um exige editar o outro.
- **Nomes de marca e de pacotes não são traduzidos** (Lucky create, CellLab +, `video_ultra_player` etc.); links de loja permanecem `/br/`.

## Observações

- A tradução é feita no cliente: buscadores e prévias sociais (og:*) enxergam apenas pt-BR.
- Novo texto traduzível = nova chave nos três idiomas em `locales.js` + atributo no HTML. Seletor e header são copiados à mão entre `index.html` e `apps.html`.
- Cache-bust manual: `?v=20261102` nos `<script>` e CSS alterados; ao mudar `locales.js`/`i18n.js` atualize o valor em todas as páginas.
